Daihon reader upscaling

The legacy reader is the default. WebGPU is opt-in in Reader settings; an
explicit saved renderer choice is respected. Anime4K stays in WebGPU only.

Legacy sampling (Android 13+)
- Catmull-Rom (default), Mitchell-Netravali, Lanczos-3, or System/bilinear.
- The original tiled decoder, cropped source bounds, fit/zoom/pan transforms,
  and system sampling during downscaling remain. Custom enlargement is gated
  on the original image's scale, not the scale of an intermediate decoded tile.
- The selected kernel samples the existing decoded bitmap directly into the
  existing destination transform through Android's AGSL RuntimeShader. No new
  resized bitmap or intermediate 2x image is made. Interpolation uses linear
  light and a float accumulator; alpha is retained. Tile edges use the source
  bitmap shader's clamp behavior. Padding only changes the viewport.
- Optional Gentle sharpening, Paper contrast and Monochrome dithering filters
  default to None. Monochrome uses an ordered 4x4 pattern; Android paint dithering
  is disabled for that choice to avoid adding a second dither.
- Settings appear in Reader > Display and the reader's Processing tab.
- Earlier Android versions and software canvases retain system sampling. On older
  Android, the in-reader choices are disabled and show System/None rather than
  saved custom options that cannot run. A
  shader rejected by the graphics stack also falls back to system sampling.
- The shader is an original Apache-2.0 implementation of standard mathematical
  reconstruction kernels; no GPL/LGPL shader or model is imported.
  Catmull-Rom uses B=0,C=1/2; Mitchell uses B=C=1/3; Lanczos-3 is sinc(x)*sinc(x/3).
  References:
  https://api.skia.org/structSkCubicResampler.html
  https://www.pbr-book.org/4ed/Sampling_and_Reconstruction/Image_Reconstruction
  https://developer.android.com/develop/ui/views/graphics/agsl/using-agsl

WebGPU
Its default Catmull-Rom upscaler and area/box downscaler are unchanged.
Paged frames prepare their high-quality tiles before presentation, avoiding the
centre-out progressive refinement being exposed as a page-turn ripple. A small
adapter isolates the pinned v54 internal full-tile API; recheck it when updating
the library. Tile-generation commands populate the cache before the base frame
presents it; the helper's transient blit is discarded.
Long-strip placement and its requested overlap remain unchanged.

The optional Anime4K DoG preset is a WGSL adaptation of bloc97's non-CNN
Anime4K_Upscale_DoG_x2.glsl, revision 7684e9586f8dcc738af08a1cdceb024cc184f426.
Original file blob: 036411fa6c2e7b57c89c8db9626bc5307f221f56.
https://github.com/bloc97/Anime4K/blob/7684e9586f8dcc738af08a1cdceb024cc184f426/glsl/Upscale/Anime4K_Upscale_DoG_x2.glsl
https://github.com/bloc97/Anime4K/wiki/Upscale-Shaders

This is the lightweight separable-Gaussian/luma-correction variant, not a CNN.
It has no model weights, inference runtime or continuous video processing.
The renderer caches its output per source image and scale. Actual power draw
and visual quality depend on the device and image; no battery measurement is
claimed. This older non-CNN variant is retained upstream but deprecated in
favor of heavier CNN presets; it is offered here explicitly as a lightweight
alternative for line art, with the original default preserved.

Port changes:
- Four small WGSL compute passes, with a three-source-pixel halo for block edges.
- Operates only when both output axes enlarge the source.
- DoG luma correction runs at the original pixel resolution, followed by the
  renderer's Catmull-Rom sampler as the single resize to the requested viewport.
  This avoids a fixed 2x intermediate and the renderer's whole-number-filter
  restriction. It is a source-space adaptation, not a pixel-identical port of
  the original 2x shader.
- The original alpha channel is preserved during luma correction.
- Original luma coefficients, Gaussian weights, 0.8 strength and local-range
  clamp retained. No default sharpening or color transform is added.
